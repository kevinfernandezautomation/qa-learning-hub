QA LEARNING HUB
OPCIONES DE BASE DE DATOS PARA ALMACENAR USUARIOS
Actualización: setiembre 2026

Objetivo
-------
Comparar alternativas para guardar usuarios, hashes de contraseña, sesiones y resultados de QA Learning Hub. Para cuentas reales, el navegador/GitHub Pages no debe conectarse directamente a la base de datos.

Arquitectura recomendada
GitHub Pages -> API HTTPS / backend -> Base de datos

1. PostgreSQL administrado
--------------------------
A) Supabase (PostgreSQL)
Tipo: relacional SQL + Auth/API opcional.
Free: US$0/mes.
Según su página de precios consultada en setiembre 2026:
- 500 MB de base de datos por proyecto;
- 50,000 usuarios activos mensuales;
- API requests ilimitadas;
- 5 GB de egress;
- 2 proyectos activos;
- los proyectos Free pueden pausarse tras 1 semana de inactividad.
Pro: desde US$25/mes.
Ventaja para este proyecto: PostgreSQL, UNIQUE email, integridad referencial y APIs/auth disponibles.
Referencia: https://supabase.com/pricing

B) Neon (PostgreSQL serverless)
Tipo: PostgreSQL administrado/serverless.
Free vigente: 10 proyectos, 0.5 GB por proyecto, hasta 5 GB total, 50 CU-hours/mes por proyecto y scale-to-zero según la información pública de precios.
Planes pagos: usage-based.
Ventaja: PostgreSQL compatible con el schema actual, ramas de base de datos y bajo costo de entrada.
Referencia: https://neon.com/pricing

2. MongoDB Atlas
----------------
Tipo: NoSQL de documentos.
Free M0: US$0; 512 MB de almacenamiento, recursos compartidos.
Flex: desde aproximadamente US$0.011/hora, hasta US$30/mes según la página de precios consultada.
Dedicated: desde aproximadamente US$56.94/mes.
Ventaja: modelo flexible JSON/documentos.
Desventaja para este proyecto: el modelo actual usa PostgreSQL relacional; migrar requeriría cambiar schema, queries y constraints.
Referencia: https://www.mongodb.com/pricing

3. Firebase / Cloud Firestore
-----------------------------
Tipo: NoSQL de documentos.
Tiene cuota gratuita para comenzar; después cobra por lecturas, escrituras, borrados, almacenamiento, index reads y red.
Ventaja: integración web rápida, tiempo real y ecosistema Google.
Riesgo: un modelo con muchas lecturas puede generar costo por operación; hay que diseñar reglas de seguridad con cuidado.
Referencia: https://firebase.google.com/docs/firestore/pricing

4. Oracle Autonomous AI Database – Always Free
----------------------------------------------
Tipo: Oracle Database relacional/SQL.
Oracle mantiene opción Always Free. La documentación indica:
- hasta 2 bases Autonomous AI Database Always Free por tenancy;
- recursos limitados incluidos;
- soporte para Oracle APEX y SQL Developer;
- la documentación de Always Free indica 20 GB de storage por base y 20 sesiones simultáneas para la configuración descrita.
Ventaja: excelente para aprender Oracle SQL, PL/SQL y Oracle APEX.
Desventaja: para un proyecto pequeño, PostgreSQL administrado suele ser más simple si el backend ya usa pg.
Referencia:
https://docs.oracle.com/en-us/iaas/autonomous-database-serverless/doc/autonomous-always-free.html

5. PostgreSQL/MySQL autogestionado
----------------------------------
Tipo: relacional.
Software: gratuito/open source.
Costo real: servidor/VPS, backups, monitoreo, actualizaciones, seguridad y administración.
Puede costar pocos dólares al mes en un VPS pequeño, pero el costo depende del proveedor y región.
Ventaja: control total.
Desventaja: usted se responsabiliza por hardening, parches, backups, recuperación y disponibilidad.

Recomendación para QA Learning Hub
----------------------------------
Piloto:
1. PostgreSQL.
2. Supabase Free o Neon Free.
3. Backend seguro que implemente registro/login.
4. Guardar password_hash, nunca contraseña.
5. UNIQUE/CITEXT sobre email para evitar duplicados.
6. Sesiones/tokens con expiración.
7. Migrar a un plan pago cuando usuarios, disponibilidad, backups o soporte lo justifiquen.

Alternativa Oracle:
Si el objetivo también es aprender Oracle APEX/PLSQL, Oracle Autonomous Always Free es una opción interesante para un ambiente educativo separado.

Estimación simple
-----------------
Etapa de prototipo: US$0/mes es posible con Free tiers, sujeto a límites.
Producción pequeña: aproximadamente US$20-US$30/mes es un punto de partida común en servicios administrados, pero el costo real depende de tráfico, storage, backups, egress y disponibilidad.
Producción creciente: usar calculadora/precios vigentes antes de presupuestar.

Seguridad mínima
----------------
- HTTPS.
- Hash Argon2id/bcrypt/scrypt en backend.
- Email normalizado y UNIQUE.
- Rate limiting.
- Email verification cuando se habilite producción.
- Password reset con token de un solo uso.
- No exponer DATABASE_URL en JavaScript.
- Backups.
- Logs sin contraseñas/tokens.
- Política de retención y borrado de datos.
