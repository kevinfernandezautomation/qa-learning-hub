ENVÍO DE CERTIFICADOS POR CORREO — INTEGRACIÓN RECOMENDADA

El prototipo v30 incluye:
- opción "Deseo recibir el certificado por correo";
- precarga del correo del usuario autenticado;
- POST a /api/certificates/email;
- fallback local si el backend todavía no está desplegado.

Producción:
1. Usuario aprueba la simulación.
2. Frontend envía email, nombre, actividad y resultado al backend.
3. Backend vuelve a validar que la persona tiene derecho al certificado.
4. Backend genera el PDF del lado servidor.
5. Backend envía correo mediante un proveedor transaccional o SMTP.
6. Guardar event ID, estado y timestamp, sin guardar contraseñas.
7. Implementar retry y manejo de bounce.

Opciones habituales:
- proveedor de email transaccional;
- SMTP de una cuenta institucional;
- servicio cloud de correo.

No es recomendable enviar el certificado exclusivamente desde JavaScript del navegador porque las credenciales de correo quedarían expuestas.

Endpoint sugerido:
POST /api/certificates/email

Body:
{
  "email": "persona@dominio.com",
  "name": "Nombre Apellidos",
  "activity": "CTFL v4.0",
  "score": 36,
  "pct": 90
}

Respuesta:
202 Accepted + request_id

Seguridad:
- autenticar usuario cuando corresponda;
- rate limiting;
- validar email;
- no aceptar HTML arbitrario;
- generar PDF desde datos del servidor;
- registrar auditoría de envío;
- evitar incluir información sensible innecesaria.
