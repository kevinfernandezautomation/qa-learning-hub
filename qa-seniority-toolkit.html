QA Engineering por seniority · Jr a Manager

QA Jr

Base operativa

Debe dominar: casos de prueba, exploración, defectos, Agile, HTTP básico y SQL básico.

Herramientas: Jira/Azure DevOps, Confluence, Postman, DevTools, SQL, Git básico, TestRail/Zephyr/Xray.

Lenguajes: fundamentos de JavaScript/TypeScript, Java o Python según el equipo.

QA Mid

Automatización mantenible

Debe dominar: UI/API automation, diseño de framework, datos, CI/CD y análisis de fallos.

Herramientas: Playwright/Cypress/Selenium, REST Assured/Karate/Postman, Pytest/JUnit/TestNG, Maven/Gradle/npm, Jenkins/GitHub Actions/Azure DevOps.

Lenguajes: TypeScript/JavaScript, Java, Python o C#.

QA Sr / SDET

Arquitectura y diagnóstico

Debe dominar: test architecture, flakiness, paralelización, microservicios, contract testing, performance, seguridad y accesibilidad.

Herramientas: Docker, Kubernetes, AWS/Azure/GCP, Pact, JMeter/k6, BrowserStack, OWASP ZAP, Grafana/Prometheus/Datadog.

Expectativa: code reviews, mentoring, root cause analysis y decisiones basadas en riesgo.

QA Lead

Estrategia de equipo

Debe dominar: estrategia, cobertura, ambientes/datos, triage, métricas, test management y mentoring.

Herramientas: Jira + TestRail/Zephyr/Xray, dashboards, CI/CD, observabilidad y reporting.

Entregables: estrategia, plan de regresión, quality gates, riesgo residual y coaching del equipo.

QA Manager

Gobierno y resultados

Debe dominar: quality strategy, governance, release readiness, KPIs/KRIs, capacidad del equipo y stakeholder management.

Métricas: defect escape rate, flakiness, cobertura útil, eficacia de pruebas, MTTR, reliability/performance y tendencias de producción.

Entregables: modelo de gobierno, políticas de release, dashboard ejecutivo, roadmap de automatización y desarrollo de talento.

Gaps añadidos al Hub

Contenido que faltaba

Se integran explícitamente TestRail/Zephyr, Karate, Maven/Gradle, Kubernetes, contract testing con Pact y observabilidad con Grafana/Prometheus/Datadog, además del bloque de governance para Lead/Manager.

Use las rutas existentes para profundizar en Playwright/Selenium/Cypress, API, bases de datos, performance, mobile, accesibilidad y CI/CD.

Interpretación: la seniority no depende de una lista fija de herramientas. Las vacantes combinan tecnologías distintas; lo importante es demostrar profundidad, mantenibilidad, razonamiento de riesgo, colaboración y resultados.
