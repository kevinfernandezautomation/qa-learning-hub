Learning Path

QA para Robótica

Ruta para probar software robótico desde componentes y ROS 2 hasta simulación, sensores, integración con hardware y regresión.

← Volver a Academia

1. Sistemas robóticos

Mapee software, actuadores, sensores, comunicaciones, estado físico y entorno. En robótica, un defecto puede surgir de la interacción entre software y mundo físico.

2. ROS 2

Comprenda nodes, topics, services, actions, parameters y QoS para diseñar pruebas de comunicación, temporización y fallos distribuidos.

3. Testing por niveles

Separe unit tests de algoritmos, integración entre nodos/componentes y system tests sobre misiones completas. Automatice donde la señal de fallo sea diagnóstica.

4. Gazebo y simulación

Gazebo permite simular física, rendering, sensores y mensajes. Use mundos reproducibles para probar antes del hardware real y conservar escenarios de regresión.

5. Sensores y ruido

Valide rangos, frecuencia, latencia, pérdida, ruido y datos fuera de distribución. Gazebo dispone de modelos para IMU, cámaras, lidar y otros sensores.

6. SIL / HIL

Progrese desde Software-in-the-Loop hacia Hardware-in-the-Loop y hardware real. Mantenga criterios equivalentes y documente diferencias de entorno.

7. Safety y recuperación

Pruebe estados seguros, timeouts, datos inválidos, degradación de sensores, pérdida de comunicación y recuperación. La severidad del riesgo debe guiar profundidad y evidencia.

8. CI, regresión y observabilidad

Versione mundos, datos y configuración; ejecute suites reproducibles y capture logs, topics, métricas y artefactos para diagnóstico.
