Learning Path · Industria financiera

QA para Banca Digital & FinTech

Aprenda a diseñar una estrategia de calidad para canales financieros con Web, API, datos, automatización, performance, accesibilidad, observabilidad y decisiones de release. Los laboratorios deben realizarse con aplicaciones de práctica, mocks, sandboxes o datos sintéticos; nunca con transacciones reales de producción.

Competencias del Learning Path

1. Dominio bancario

Cuentas, saldos, movimientos, transferencias, tarjetas, pagos, préstamos y solicitudes. Modele reglas, estados, límites, reversos, duplicados y trazabilidad.

2. Web y API

Diseñe pruebas UI, REST y contract testing; valide códigos HTTP, esquemas, autorización, errores, idempotencia y correlación entre canal y backend.

3. Datos y reconciliación

Use SQL para validar precisión, consistencia, duplicados, integridad y conciliación entre movimientos, saldos y estados.

4. Automatización

Construya suites mantenibles con Playwright/Pytest/Postman, Page Objects, fixtures, datos sintéticos, mocks, tags, paralelización, evidencias y reportes.

5. Performance y resiliencia

Modele carga, estrés, picos y capacidad. Analice latencia p95/p99, throughput, errores y degradación sin probar destructivamente contra producción.

6. Calidad no funcional

Incluya accesibilidad, responsive, compatibilidad, usabilidad, observabilidad, privacidad y seguridad como atributos de calidad.

7. CI/CD y release

Implemente smoke, regresión, quality gates, trazabilidad de evidencia, defect trends y criterios Go/No-Go.

8. Capstone

Prepare una estrategia de QA para una banca ficticia: mapa de riesgos, Test Plan, API suite, UI suite, SQL checks, performance baseline, dashboard y recomendación de release.

Caso de estudio público: BAC Costa Rica

Como ejercicio de análisis, el catálogo adjunto toma únicamente funcionalidades públicamente documentadas por BAC —por ejemplo banca en línea/móvil, cuentas, transferencias, pagos, tarjetas y préstamos— y las transforma en ideas de prueba. No contiene credenciales, datos privados ni instrucciones para operar sistemas internos.

Objetivo educativo: aprender a convertir funcionalidades bancarias públicas en cobertura de pruebas, riesgos y oportunidades de mejora. La ejecución debe hacerse únicamente con autorización y en ambientes controlados.

Laboratorio público: automatización de Préstamo Personal BAC

Este laboratorio convierte la página pública de Préstamo Personal en un caso educativo de Quality Engineering. Incluye ejemplos TypeScript/Playwright para pruebas funcionales, accesibilidad, responsive, compatibilidad, rendimiento ligero, contenido/SEO y una guía separada de seguridad para ambientes autorizados.

Límite de ejecución: los ejemplos públicos no envían solicitudes de crédito, no usan credenciales y no generan carga. Seguridad activa, carga/estrés, APIs privadas y transacciones deben probarse únicamente en sandbox o QA con autorización.

Laboratorio de automatización móvil · App bancaria

Aprenda a convertir un flujo móvil de banca digital en pruebas automatizadas con Appium + WebdriverIO + TypeScript, manteniendo autenticación, transferencias y datos financieros en una app demo, mock o sandbox autorizado. El caso cubre login, biometría/token simulados, cuentas, Transferir o pagar, favoritos, monto/detalle, comprobante, recursos rotos, resiliencia y CI/CD.

Enfoque seguro: los ejemplos no incluyen identificadores internos de la app BAC, credenciales, endpoints privados ni ejecución de transferencias reales. La automatización transaccional se diseña para entornos QA autorizados.
