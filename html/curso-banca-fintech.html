Curso práctico · Financial Quality Engineering

QA para Banca Digital & FinTech

Curso práctico para diseñar calidad de extremo a extremo en una banca ficticia. Use exclusivamente demos, mocks, sandboxes y datos sintéticos; no ejecute carga, seguridad ni transacciones sobre sistemas bancarios reales sin autorización formal.

← Volver al pathComenzar curso
Módulo

1. Dominio y riesgo financiero

Modele cuentas, movimientos, transferencias, pagos, tarjetas, préstamos, estados, límites, reversos, duplicados y trazabilidad. Priorice por impacto y probabilidad.

Práctica: Mapa de riesgos de una banca ficticia.

Módulo

2. Web y Mobile QA

Diseñe casos funcionales, exploratorios, accesibilidad, responsive, compatibilidad y resiliencia. Automatice flujos seguros con Playwright/Appium sobre demos.

Práctica: Suite smoke Web/Mobile en aplicación de práctica.

Módulo

3. API y contratos

Pruebe REST, autenticación simulada, códigos HTTP, esquemas, errores, idempotencia y correlación UI-backend. Use Postman/Newman o código.

Práctica: Colección API con positivos, negativos y contrato.

Módulo

4. Datos y reconciliación

Use SQL sobre datos sintéticos para verificar integridad, duplicados, saldos, movimientos y conciliación entre sistemas.

Práctica: Consultas de reconciliación en base de práctica.

Módulo

5. Automatización mantenible

Aplique Page/Screen Objects, fixtures, datos sintéticos, mocks, tags, paralelización, evidencias y reportes.

Práctica: Mini framework con UI + API + datos.

Módulo

6. Performance y resiliencia

Modele baseline, carga, estrés, spike y capacidad solo en ambientes autorizados. Analice throughput, response time, P90/P95/P99 y error rate.

Práctica: JMeter/k6 contra endpoint demo o mock.

Módulo

7. Observabilidad y diagnóstico

Correlacione síntomas del cliente con métricas de aplicación, infraestructura y datos; practique Grafana/Prometheus conceptualmente o en laboratorio local.

Práctica: Informe de cuello de botella simulado.

Módulo

8. Seguridad y privacidad desde QA

Valide autorización, manejo seguro de sesión, datos sensibles sintéticos, logging y controles básicos sin realizar pentesting no autorizado.

Práctica: Checklist de seguridad QA y privacidad.

Módulo

9. CI/CD y release readiness

Automatice smoke/regresión, evidencias y quality gates. Defina criterios Go/No-Go basados en riesgo y defectos abiertos.

Práctica: Pipeline educativo y Release Readiness Report.

Módulo

10. IA aplicada a QA financiero

Use IA para proponer casos, revisar scripts, agrupar defectos y resumir resultados; no comparta credenciales, PII, datos bancarios ni arquitectura confidencial.

Práctica: Revisión humana de un set de casos generado con IA.

Módulo

11. Métricas de calidad

Mida cobertura, defect leakage, pass rate, duración de regresión, estabilidad de automatización, tiempos de respuesta y tendencias.

Práctica: Dashboard simple con interpretación y acciones.

Módulo

12. Capstone FinTech

Integre estrategia, riesgo, Web/Mobile/API, SQL, performance, CI/CD, observabilidad y reporte ejecutivo para una banca totalmente ficticia.

Práctica: Test Strategy + suites + evidencia + decisión de release.

Ruta QA para el sector financiero

14–18 h · Intermedio–Avanzado · 17 módulos

  1. Arquitectura de banca digital y mapa de riesgos
  2. Autenticación, sesiones, MFA y recuperación segura
  3. Cuentas, saldos, movimientos y estados de cuenta
  4. Transferencias internas, interbancarias y SINPE: reglas, límites e idempotencia
  5. Tarjetas: pagos, bloqueo/desbloqueo, PIN y controles
  6. Préstamos y solicitudes digitales: estados, reglas y evidencia
  7. Pagos de servicios, municipalidades y débitos automáticos
  8. API Quality Engineering: REST, contratos, errores, autorización y trazabilidad
  9. SQL y reconciliación: integridad, precisión, duplicados y consistencia
  10. Automatización Web/API con Playwright, Pytest y Postman/Newman
  11. Performance: concurrencia, p95/p99, capacidad, resiliencia y degradación controlada
  12. Accesibilidad, responsive, compatibilidad y UX en canales financieros
  13. Observabilidad, logs, correlation IDs, métricas y diagnóstico
  14. CI/CD, quality gates, regresión y release readiness
  15. Automatización TypeScript/Playwright aplicada a una página bancaria pública sin transacciones
  16. ISO/IEC 25010:2023 aplicado a banca y trazabilidad con ISTQB
  17. Capstone: estrategia de QA para una banca digital ficticia con matriz de riesgo y suite automatizada

Ruta 1 · QA financiero empresarial

Analista de Calidad de Software — Perfil BN Fondos

Aprenda a preparar ambientes y validar sistemas financieros que utilizan tecnologías Microsoft, Oracle y servicios web.

8 módulos · 164 horas orientativas · Nivel intermedio

  • ISTQB CTFL: técnicas, planificación y evidencias.
  • ISO/INTE, SGE, auditoría y mejora continua.
  • Scrum, experiencia del cliente, Design Thinking y Design Sprint.
  • C#, Visual Studio, ASP.NET Web Forms/ASPX, JavaScript y jQuery.

  • Analítica QA, Power BI, ITIL, COBIT y gestión de cambios.

Simulación de sistema de inversiones con datos ficticios: matriz de trazabilidad, 20 casos de prueba, consultas SQL, pruebas de servicio SOAP, reporte de defectos y tablero de calidad.

Ruta 2 · QA sector público y desarrollo .NET

Profesional y Especialista en Calidad de Software — Perfiles bachillerato y licenciatura

Prepárese para pruebas complejas, automatización de Web APIs y trabajo conjunto con equipos de desarrollo y plataformas CI/CD.

10 módulos · 180 horas orientativas · Dos niveles: profesional y especialista

  • Scrum, Shift-Left, requisitos funcionales y no funcionales.
  • Pruebas exploratorias, manuales, de regresión y basadas en riesgos.
  • Web APIs .NET 8+ con C#, POO, Dapper y JWT.
  • JavaScript, HTML, CSS, UX/UI y arquitectura modular.
  • SQL Server y PostgreSQL: consultas y validación de datos.
  • Git, automatización API y Azure DevOps CI/CD.
  • Coordinación de QA, estrategia, métricas y revisión de calidad.
Diferencias entre niveles

Profesional bachiller: ejecución de pruebas, colaboración técnica y fundamentos de automatización. Especialista licenciatura: liderazgo/coordinación, estrategias de pruebas complejas, pipelines, desarrollo e integración de componentes. Los requisitos académicos, de colegiatura y experiencia son externos al curso.
