Práctica Oracle: tablas, APEX y reportes

Cree dos tablas relacionadas, consulte sus datos con SQL, construya una aplicación en Oracle APEX y diseñe un reporte en Reports Builder.

6 etapas · Ejemplos SQL · Autoevaluación · Simulación sin conexión a Oracle

1. Requisitos y modelo relacional

Una organización requiere cuentas de usuario y fichas personales. Cada usuario puede tener como máximo una ficha, y ninguna ficha puede existir sin su usuario.

Criterios de aceptación

  • Estado ACTIVO/INACTIVO; rol ADMIN/CONSULTA.

2. Crear las tablas en Toad for Oracle

En Toad for Oracle puede crear las tablas desde la interfaz gráfica (Create Table) o desde Editor. Elija una ruta y compruebe que la tabla quedó guardada en el esquema correcto.

Ruta A · Crear una tabla desde la interfaz de Toad

  1. Conéctese a Oracle. Abra Toad y seleccione su conexión. Anote el usuario/esquema activo. Puede comprobarlo con SELECT USER FROM dual;.
  2. Abra Schema Browser. Use el menú Database → Schema Browser (la ubicación puede variar por versión). Seleccione el esquema propietario y la categoría Tables.
  3. Abra Create Table. En la categoría Tables, utilice el botón de crear objeto o clic derecho → Create Table. También puede encontrarlo desde Database → Create → Table, según su versión.
  4. Configure USUARIOS. Nombre: USUARIOS. En la pestaña de columnas, agregue cada nombre, tipo, longitud y opción NOT NULL indicados en la etapa 1. Defina USUARIO_ID como clave primaria e identidad si la versión lo admite.
  5. Agregue restricciones. En las secciones de constraints/keys configure la PK, las restricciones UNIQUE y CHECK. Antes de confirmar, revise el SQL/DDL generado por Toad.
  6. Ejecute Create/OK. Espere el mensaje de éxito. Repita el proceso con INFORMACION_USUARIO, indicando que USUARIO_ID referencia USUARIOS(USUARIO_ID) y es UNIQUE.
  7. Actualice el árbol. Regrese a Schema Browser → Tables, pulse Refresh (a menudo F5) y busque USUARIOS e INFORMACION_USUARIO. Seleccione cada una para ver Columns, Constraints y Data. Si no aparecen, revise el esquema seleccionado, los filtros y si la operación terminó sin error.
  8. Compruebe los datos. Después de ejecutar los INSERT de la etapa 3, seleccione la tabla y abra su pestaña Data, o ejecute SELECT * FROM usuarios; en Editor. Crear la tabla solo crea su estructura: estará vacía hasta insertar filas.

Ruta B · Crear desde Editor

Abra Editor, copie el DDL de abajo y ejecute las sentencias de creación. Si ya creó las tablas mediante la interfaz, no vuelva a ejecutar CREATE TABLE: aparecerá ORA-00955 por objeto existente.

Si ve cero filas: la tabla sí existe, pero aún no tiene datos. Ejecute los INSERT de la etapa 3 y confirme con COMMIT. Si APEX no muestra la tabla, compruebe que Toad y APEX apuntan a la misma base de datos y al mismo esquema, o que existen permisos apropiados.

Una restricción CHECK no puede depender de SYSDATE. Valide la fecha de nacimiento en APEX y, para protección a nivel de base de datos, utilice un trigger apropiado.

4. Construir el aplicativo Oracle APEX
SQL Workshop y App Builder son herramientas diferentes. SQL Workshop permite crear y consultar tablas; App Builder sirve para construir las pantallas. Ejecutar una sentencia en SQL Commands o SQL Scripts no crea automáticamente una aplicación.
Desde el inicio de sesión hasta ver las tablas
  1. Abra la URL de Oracle APEX proporcionada por su organización. Ingrese Workspace, usuario y contraseña. La pantalla y la URL dependen de la instalación.
  2. En la página principal del workspace, abra SQL Workshop → Object Browser. Seleccione Tables y busque USUARIOS e INFORMACION_USUARIO. Puede revisar columnas y datos desde allí.
  3. Si no aparecen, vaya a SQL Workshop → SQL Commands y ejecute SELECT USER FROM dual; y la consulta a USER_TABLES de la etapa 2. Verifique el esquema asignado al workspace. Si la tabla se creó en otro esquema, solicite permisos al administrador; no se transfiere automáticamente.
  4. Si creó las tablas desde SQL Workshop → SQL Commands, vuelva a Object Browser y actualice la lista. Si las creó en Toad, asegúrese de utilizar la misma instancia y el mismo esquema.
  5. Regrese a la página principal del workspace y entre a App Builder → Create → New Application. Nombre sugerido: Gestión de usuarios. Agregue una página de reporte interactivo basada en USUARIOS y su formulario de edición.
  6. Agregue una página de formulario para INFORMACION_USUARIO. Cree un elemento de selección de usuario cuyo valor de retorno sea USUARIO_ID y cuyo texto visible sea NOMBRE_USUARIO.
  7. En SQL Workshop → SQL Commands, ejecute el SQL de la vista de la etapa 5. En App Builder agregue otra página Interactive Report con fuente VW_REPORTE_USUARIOS.
  8. Guarde los cambios, ejecute la aplicación con Run Application, autentíquese si se solicita y pruebe altas, consultas, filtros y relaciones.

5. Reportes con Oracle APEX Data Reporter / SQL Developer
Cree una vista que consolide las dos tablas. Luego utilícela como fuente del reporte.
Oracle Reports Builder 6i / entorno heredado «6.5»
Si la herramienta muestra Object Navigator, Data Model, Layout Model y Live Previewer, está trabajando con la familia clásica de Oracle Reports Builder. No es lo mismo que APEX Data Reporter ni que los reportes de SQL Developer. El nombre «Oracle Database Reporter 6.5» no identifica con certeza una edición oficial; esta guía sigue la interfaz de Reports Builder 6i y debe adaptarse si su instalación difiere.
  1. Abra Reports Builder. Seleccione File → New → Report y elija Use the Report Wizard. Para comenzar seleccione estilo Tabular (una fila por usuario), título «Reporte de usuarios».
  2. Conecte la fuente de datos. Seleccione SQL Query / SQL statement. Introduzca una consulta SELECT sobre VW_REPORTE_USUARIOS o una consulta JOIN directa. La conexión a Oracle debe ser válida y el usuario debe tener SELECT sobre los objetos.
  3. Seleccione campos. Pase a Displayed Fields los campos NOMBRE_USUARIO, NOMBRE_COMPLETO, CORREO, ESTADO y ROL. Defina encabezados, orden y ancho de columnas.
  4. Seleccione plantilla y termine. La template define el estilo general; no sustituye el modelo de datos ni genera por sí sola las columnas. Pulse Finish para crear el diseño inicial.
  5. Revise Data Model. En el Report Editor abra Data Model (en 6i, desde el Object Navigator). Debe verse la consulta Q_1 y sus campos. Si no aparecen, revise la consulta SQL y la conexión.
  6. Diseñe visualmente. Cambie a Layout Model (en versiones posteriores, Paper Layout). Modifique títulos, etiquetas, posiciones, tamaños y repeating frames. Estos marcos repiten una fila por cada registro; los campos se vinculan con las columnas del Data Model.
  7. Previsualice. Abra Live Previewer (en versiones posteriores, Paper Design) o ejecute el diseño. Compruebe que se muestren los registros y que las columnas no se corten.
  8. Guarde el diseño. Utilice File → Save As y conserve el archivo del reporte (por ejemplo, usuarios.rdf, según las opciones de su versión). La exportación a PDF dependerá del entorno y su configuración.

¿Qué es un trigger y cuándo se usa?
Un trigger de base de datos es un bloque PL/SQL que se ejecuta automáticamente ante un evento como INSERT, UPDATE o DELETE. Por ejemplo, se puede impedir una fecha de nacimiento futura aunque los datos se registren desde Toad, APEX u otro sistema. No confunda ese trigger con un format trigger de Reports Builder, que controla el formato o visibilidad de objetos durante la presentación del reporte.
CREATE OR REPLACE TRIGGER trg_info_fecha_nacimiento
BEFORE INSERT OR UPDATE OF fecha_nacimiento
ON informacion_usuario
FOR EACH ROW
BEGIN
  IF :NEW.fecha_nacimiento > SYSDATE THEN
    RAISE_APPLICATION_ERROR(-20001,
      'La fecha de nacimiento no puede ser futura');
  END IF;
END;
/
En este ejemplo el trigger se ejecuta automáticamente antes de insertar o modificar una fecha. Si la condición falla, Oracle rechaza la operación. El símbolo :NEW representa el nuevo valor de la fila. Ejecute el bloque en una herramienta SQL compatible con PL/SQL y valide el resultado con un caso positivo y uno negativo.
Alternativas si no utiliza Reports Builder clásico
APEX Data Reporter: cree un dataset sobre la vista y después una aplicación de reportes, si la función está disponible. SQL Developer: View → Reports → User Defined Reports → New Report, configure el SQL y ejecute. Estas rutas son diferentes del diseñador visual de Reports Builder.


6. Pruebas de aceptación y evaluación

Preguntas de entrevista técnica · Oracle APEX y Reports
Responda primero sin consultar la solución. Abra cada pregunta para comparar su respuesta con el ejemplo y justificarla.
¿Qué es una acción dinámica en Oracle APEX?
Es una regla declarativa de interfaz que responde a eventos (por ejemplo, Change o Click) y ejecuta acciones sin programar manualmente toda la lógica JavaScript. Ejemplo: al elegir INACTIVO, ocultar un campo o mostrar una advertencia.
¿Cuáles esquemas de autenticación existen? Brinde dos ejemplos.
La autenticación verifica quién ingresa. Ejemplos: Oracle APEX Accounts (cuentas del workspace, cuando está disponible) y Social Sign-In / OpenID Connect mediante un proveedor de identidad. También existen esquemas personalizados o basados en cabeceras, según versión y configuración.
¿Cuáles esquemas de autorización existen? Brinde dos ejemplos.
La autorización decide qué puede hacer un usuario autenticado. Ejemplos: esquema de tipo Is In Role para permitir ADMIN y esquema PL/SQL Function Returning Boolean que consulte una regla o tabla de permisos. Los tipos disponibles dependen de la versión.
¿Qué es DML? Brinde un ejemplo.
Data Manipulation Language: sentencias que consultan o modifican filas; en el uso común de Oracle, INSERT, UPDATE y DELETE son DML. Ejemplo: UPDATE usuarios SET estado = 'INACTIVO' WHERE usuario_id = 1; (con COMMIT si corresponde).
¿Qué es el estado de sesión de APEX? Brinde un ejemplo.
Es el conjunto de valores de elementos y variables que APEX conserva durante una sesión. Ejemplo: P3_USUARIO_ID=25; una página de detalle puede usar ese valor para recuperar el usuario 25. No equivale a una variable global compartida por todos.
¿Qué es la protección del estado de sesión? Brinde un ejemplo.
Session State Protection (SSP) restringe cambios no autorizados de valores mediante URLs o solicitudes, utilizando controles como checksums. Ejemplo: impedir que alguien altere P3_USUARIO_ID en la URL para consultar otro registro sin permiso. SSP complementa, pero no sustituye, la autorización por registro.
¿Qué es APEX_COLLECTION?
Es una API de APEX para mantener colecciones temporales de datos por sesión, sin crear una tabla permanente para cada borrador. Ejemplo: guardar temporalmente usuarios seleccionados para revisión antes de confirmar una operación. Se administra con el paquete APEX_COLLECTION.
¿Cuál es la diferencia entre un trigger de Oracle Database y un format trigger de Reports Builder?
El primero se ejecuta por eventos sobre tablas y puede validar datos; el segundo controla la presentación de un objeto en un reporte. Un format trigger no reemplaza una restricción de integridad de base de datos.
¿Cómo se relacionan las tablas y cómo se muestra el nombre completo?
INFORMACION_USUARIO.USUARIO_ID referencia USUARIOS.USUARIO_ID. La restricción UNIQUE establece una ficha como máximo por usuario. Use LEFT JOIN y concatene NOMBRE, PRIMER_APELLIDO y SEGUNDO_APELLIDO con || y NVL2.
¿Por qué no aparecen las tablas en el inicio de APEX después de ejecutar el worksheet?
El worksheet/SQL Workshop crea objetos en un esquema, pero no agrega páginas automáticamente a App Builder. Revise SQL Workshop → Object Browser, el esquema de análisis, la conexión y los permisos. Después cree la app en App Builder.
