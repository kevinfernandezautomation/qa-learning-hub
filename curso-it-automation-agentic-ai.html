Curso práctico · Automation Engineering

Automatización de TI & Agentes de IA

Curso de 16 módulos alineado con automatización empresarial moderna. Cada módulo combina concepto, decisión de arquitectura, práctica segura y evidencia. Los ejercicios usan mocks, datos sintéticos o sandboxes.

← Volver al pathComenzar curso
Resultado esperado: diseñar automatizaciones mantenibles y un agente de TI con herramientas controladas, pruebas, seguridad, CI/CD y métricas de impacto.
Módulo

0. Python, JavaScript y PowerShell para automatización

Use Python para scripts, APIs, archivos, validación y orquestación; JavaScript/TypeScript para integraciones web y automatización; PowerShell para administración de entornos Microsoft y Power Platform. Practique configuración externa, logging, manejo de errores, reintentos y funciones reutilizables.

Práctica: Laboratorio: normalice un CSV/JSON, consulte una API simulada y genere un reporte auditable.

Módulo

1. REST, servicios web, mensajería, SQL y NoSQL

Compare REST/JSON y servicios web; diseñe contratos, autenticación, timeouts, retries y webhooks. Estudie colas/eventos para desacoplar productores y consumidores. Seleccione SQL cuando importan relaciones/transacciones y NoSQL cuando predominan esquema flexible, distribución o patrones de acceso específicos.

Práctica: Laboratorio: API mock + cola simulada + SQL/NoSQL de práctica con correlación de ID.

Módulo

2. RPA y low-code/no-code

Aprenda cuándo conviene API/código y cuándo RPA. Power Automate ofrece flujos cloud, programados y desktop; Automation Anywhere representa el patrón empresarial de bots y automatización de procesos. Incluya excepciones, credenciales, gobierno y trazabilidad.

Práctica: Laboratorio: automatice una solicitud ficticia y compare RPA vs API.

Módulo

3. Infraestructura como código y Ansible

Ansible usa playbooks YAML y un modelo declarativo. Trabaje inventarios, variables, módulos, roles, handlers y check mode. Diseñe tareas idempotentes: repetir la automatización no debería alterar un sistema que ya está en el estado deseado.

Práctica: Laboratorio: playbook de sandbox para validar/configurar un servicio ficticio, primero en check mode.

Módulo

4. IA generativa, LLM y prompt engineering

Comprenda tokens, contexto, instrucciones, grounding, salidas estructuradas, temperatura conceptual, límites y evaluación. Diseñe prompts con objetivo, contexto, restricciones, formato esperado y criterios de calidad; trate la salida como probabilística y verificable.

Práctica: Laboratorio: convertir un ticket de TI ficticio en JSON estructurado y evaluar consistencia.

Módulo

5. Diseño de agentes

Un agente combina modelo, instrucciones y herramientas. Estudie tools/function calling, memoria/estado, handoffs entre agentes especializados, guardrails, trazas y orquestación. Aplique mínimo privilegio y confirmación humana para acciones sensibles.

Práctica: Laboratorio: agente de triage que deriva solicitudes a diagnóstico, documentación o escalamiento.

Módulo

6. Agentes para automatización de TI y asistentes internos

Modele casos como clasificación de tickets, consulta de inventario autorizado, diagnóstico guiado, generación de runbooks y resumen de incidentes. Separe recomendación de ejecución y limite herramientas a acciones permitidas.

Práctica: Laboratorio: asistente interno sobre datos sintéticos con registro de cada decisión.

Módulo

7. Git, branching, pull requests y revisión/certificación de código

Practique ramas pequeñas, commits claros, pull requests, revisiones, CODEOWNERS conceptuales y checks obligatorios. Certifique una automatización solo cuando cumple funcionalidad, pruebas, seguridad, mantenibilidad y evidencia.

Práctica: Laboratorio: PR ficticio con checklist, revisión y quality gate.

Módulo

8. Pruebas automatizadas para automatización e IA

Cubra unitarias, integración, contrato, E2E y regresión. Para IA, agregue datasets de evaluación, assertions deterministas donde sea posible, tolerancias, casos adversos seguros y verificación de herramientas/handoffs.

Práctica: Laboratorio: pytest sobre una herramienta y evaluación repetible del resultado estructurado de un agente.

Módulo

9. Secure development

Nunca incruste secretos en código. Aplique variables/secret stores, mínimo privilegio, validación de entrada, allowlists de herramientas, dependencias actualizadas, logs sin datos sensibles y trazabilidad. Revise amenazas antes de automatizar acciones con impacto.

Práctica: Laboratorio: detectar secretos ficticios, validar entradas y producir audit log sanitizado.

Módulo

10. CI/CD: build, test, quality gates y despliegue

Construya pipelines que ejecuten lint, unit tests, integration tests, análisis de dependencias y gates antes del despliegue. GitHub Actions es un ejemplo de plataforma para automatizar build, test y deployment ante eventos del repositorio.

Práctica: Laboratorio: pipeline educativo que bloquee merge cuando falla una prueba.

Módulo

11. Cloud y arquitecturas modernas

Estudie servicios gestionados, eventos, microservicios, contenedores y serverless. En arquitectura dirigida por eventos, productores y consumidores se desacoplan mediante canales/brokers; contenedores y serverless permiten escalar distintos componentes de forma independiente.

Práctica: Laboratorio: diagrama de una automatización API → evento → worker → base de datos → evidencia.

Módulo

12. Soluciones escalables, reutilizables e idempotentes

Separe dominio, adaptadores, herramientas y orquestación. Diseñe configuración externa, contratos versionados, retries con backoff, timeouts, deduplicación, idempotency keys, colas y observabilidad. Reutilizable no significa genérico sin límites.

Práctica: Laboratorio: ejecutar dos veces la misma solicitud sin duplicar el efecto simulado.

Módulo

13. Agile, Scrum, Design Thinking y equipos multidisciplinarios

Use Scrum para trabajo complejo con equipos pequeños, multifuncionales y autogestionados; complemente con descubrimiento centrado en usuario: entender problema, idear, prototipar, validar y aprender. Conecte ingeniería, seguridad, operaciones y negocio.

Práctica: Laboratorio: convertir una necesidad en hipótesis, backlog, prototipo y criterios de aceptación.

Módulo

14. Métricas de impacto

Defina baseline y mida tiempo ahorrado, lead time, tasa de éxito, errores/retrabajo evitados, adopción, costo por ejecución, disponibilidad y experiencia. No confunda volumen automatizado con valor: compare antes/después y documente supuestos.

Práctica: Laboratorio: dashboard simple con baseline, meta, resultado y evidencia.

Módulo

15. Capstone: agente de TI seguro

Construya un agente educativo que recibe una solicitud, valida alcance, consulta una API simulada, decide entre herramientas permitidas, ejecuta una acción controlada en sandbox y genera evidencia. Debe incluir guardrails, autorización, idempotencia, logs, pruebas y pipeline.

Práctica: Entregables: arquitectura, threat checklist, código, pruebas, CI, trazas, métricas y demo con datos sintéticos.
