Laboratorio ficticio

Aprenda IEC 62304 siguiendo el ciclo de vida de un software médico

CardioDose Controller es un producto educativo ficticio que calcula y presenta parámetros de apoyo para personal clínico usando datos sintéticos. No toma decisiones clínicas reales.

← Volver a Medical QA LabIr a laboratorio ISO 13485 →Ver todos los laboratorios
Alcance: IEC 62304 define un marco de procesos, actividades y tareas para el ciclo de vida del software de medical devices. Este laboratorio parafrasea conceptos públicos; no reproduce el texto de la norma ni sustituye capacitación regulatoria.
1

Planifique el desarrollo

Situación: el equipo iniciará la versión 2.0.

  1. Defina alcance y componentes software.
  2. Liste actividades, responsables y entregables.
  3. Defina cómo se controlarán versiones, defectos y cambios.
  4. Relacione actividades de software con gestión de riesgo.
Entregable ficticio: Software Development Plan v2.0.
2

Convierta necesidades en requisitos software

Ejemplo: “El sistema debe registrar el cálculo junto con usuario, timestamp y algoritmo utilizado”.

  1. Vuelva el requisito observable.
  2. Asigne ID SWR.
  3. Relacione riesgo/control.
  4. Defina cómo se verificará.
Entregable: SRS con trazabilidad.
3

Diseñe arquitectura

Separe UI clínica, motor de cálculo, persistencia y audit log.

  1. Identifique interfaces.
  2. Defina responsabilidades.
  3. Marque componentes relacionados con controles de riesgo.
  4. Defina manejo de errores.
Entregable: arquitectura + interfaces.
4

Implemente y verifique unidades

El motor de cálculo se implementa como componente independiente.

  1. Versione código.
  2. Realice review.
  3. Ejecute unit tests.
  4. Conserve resultados y build.
Entregable: código + unit test evidence.
5

Integre componentes

Conecte UI → motor → base de datos → audit log.

  1. Defina orden de integración.
  2. Pruebe interfaces y fallos.
  3. Registre versiones de cada componente.
  4. Documente anomalías.
Entregable: integration test record.
6

Ejecute system testing

Pruebe el software integrado contra requisitos definidos.

  1. Seleccione requisitos/riesgos.
  2. Prepare datos sintéticos.
  3. Ejecute casos.
  4. Adjunte evidencia y resultado.
Entregable: system test report.
7

Controle configuración y problemas

Se detecta DEF-204: audit log no registra el algoritmo.

  1. Abra defecto reproducible.
  2. Relacione build afectado.
  3. Corrija bajo control de cambio.
  4. Ejecute confirmation test y regresión.
Entregable: defect → change → retest evidence.
8

Prepare mantenimiento

Después del release aparece un cambio solicitado en el algoritmo.

  1. Analice impacto.
  2. Actualice requisitos/riesgo.
  3. Controle nueva versión.
  4. Repita verificación afectada.
Entregable: maintenance/change package.
Importante: la página oficial de IEC indica que IEC 62304 cubre desarrollo y mantenimiento del software médico y no cubre por sí sola la validación y liberación final del medical device completo.
